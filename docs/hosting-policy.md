# 本人用公開の提案（未決定）

2026-10-20に公式料金・仕様を確認して作成した#23の検討案。**以下は利用者の承認前の候補であり、構成を確定した記録ではない。** クラウドの契約・課金リソース作成・ドメイン購入・ログイン方式の実装は行っていない。

## 推奨する具体案

| 項目 | 候補 |
|---|---|
| Vueの配信 | Cloudflare Pages Free。Vueのビルド成果物だけを配信 |
| Nest | Compute Engine e2-micro 1台、us-west1、単一APIプロセス |
| ディスク | 標準永続ディスク合計30GB以内。例：起動20GB＋DB用10GB。DB用はVM削除時に自動削除しない |
| 公開経路 | VMの外部IPv4 1個、API用ホスト名、Caddy等でHTTPSを終端しDockerのAPIへ転送 |
| URL | 画面はPagesの提供URL、APIは `api.{利用者のドメイン}`。実際の名前は未決定 |
| 本人制限 | Googleでログイン。NestでGoogle ID tokenを検証し、事前設定した本人のsubだけ許可 |
| 複数端末 | 同じGoogleアカウントで利用。DBは共通、端末の未送信仕分けはそのブラウザだけに残る |
| バックアップ | 同地域の非公開Cloud Storage Standardへ毎日1回、7日分。許容損失は最大約24時間＋失敗が続いた時間 |

Googleの検証はgoogle-auth-libraryを使い、署名・aud・iss・expと本人subを確認する案。Googleにログインしているだけで全員を許可したり、最初にアクセスした人を自動で所有者にしたりしない。フロントのID tokenはメモリで扱い、期限切れなら再ログインへ誘導する。未送信仕分けは保持し、保存成功と誤表示しない。CORSは正規の画面originだけを許す別設定とし、認証の代わりにしない。

この案ならGoogleログインはアプリ側だけで実装する。Cloudflare Accessを選ぶ場合は入口で保護する別案を詰め、Googleログインを重ねて追加しない。Vercelを選ぶ場合も同じSPA・API構成は使えるが、今回は配信を一つに絞るためCloudflareを候補にした。

公開時は80/443をHTTPS用、管理SSHはIAP等の管理経路に限定し、3000を外部に開かない。API用ドメインがない場合は新規取得費用を見積もるか、ドメイン不要の別公開経路を再検討する。米国VMの往復遅延とe2-microの実メモリは配置後に確認し、余力が不足しても承認なくサイズを上げない。ビルドはCI等で済ませてVMへ配布する。

## 月額の試算

公式USD料金を元に、730時間/月、対象の無料枠を他用途で消費していないことを仮定する。円換算の150円/USDは**計算例の仮定**であり、現在の為替やGCPの請求レートではない。税・請求通貨・実際の利用量で変動する。

| 項目 | 条件と試算 |
|---|---|
| e2-micro | us-west1/us-central1/us-east1の対象時間内なら無料枠。複数VM・他プロジェクトの合計利用に注意 |
| 標準永続ディスク | 合計30GB-month以内なら無料枠。pd-balanced/SSDや合計超過分は別料金 |
| 外部IPv4 | 使用中でも$0.005/時間。月の無料1時間を除いて約$3.65。未使用の予約IPは$0.01/時間 |
| VMの通信 | 北米からの対象送信は1GB/月まで無料枠。超過・宛先・別サービスの経路で追加料金。収集するメタデータ以外の動画/音声をVMで中継しない |
| Cloudflare Pages | 静的配信はFree枠。月500ビルド、20,000ファイル、単一25MiBの制限内。Functionsはこの案では使わない |
| バックアップ | 例：1回1GiB、7日分＋削除後のsoft delete保持7日で最大約14GiB相当。対象の5GB-month無料枠を約9GiB超える場合は約$0.18/月（約$0.02/GiB-month）。実サイズと履歴で再計算 |
| 保存API操作 | StandardのClass Aは$0.005/1,000回。月30回なら約$0.00015。無料枠の残量で変動。復元の読出し・外向き転送も別途確認 |
| ドメイン | 所有済みなら追加取得なし。新規取得・更新料はドメイン選択後に年額÷12を加算 |
| ログ・イメージ | Dockerのローカルログは上限を設定済み。外部ログ転送・有料レジストリは未採用。採用時は別見積もり |

この仮定で固定部分は約$3.83/月、例示レートなら約575円＋ドメイン年額÷12＋税・追加利用。月1,000円以内を保証する数字ではない。無料枠の対象外地域・サイズ、複数台、ディスク種類、ロードバランサーやCloud NATを選ぶ場合はこの試算を使わず作成前に見直す。無料枠がなければVMとディスクも別見積もりが必要。

予算は対象プロジェクトで月1,000円、50%/80%/100%と予測超過の通知を候補にする。**通知だけのbudgetは利用や課金を自動停止しない。** 新しいspend cap機能もサービスごとの適用条件・遅延があるため、設定しただけでこのVMの総費用が必ず1,000円で止まるとは扱わない。

## 資格情報と権限の案

GoogleのWeb client IDはフロントへ公開してよい設定。本人sub・APIの許可origin・公開URLはサーバーの設定に置く。GitHub tokenを使う場合はVM上のGit管理外ファイル（所有者だけ読める権限）へ置く。Googleログインのために利用者のパスワードやリフレッシュトークンをアプリへ保存しない。

VMのサービスアカウントはバックアップ用バケットへの必要な権限だけに限定する。JSON鍵を配布せずVMのサービスアカウントを利用する。日付付きオブジェクトの作成はStorage Object Creator、世代の削除はバケットのlifecycleへ分ける案。復元する管理者には対象バケットのObject Viewerを別に付ける。Compute Engine・ディスク・ネットワークの作成権限と課金/予算の権限は、配布用の常用サービスアカウントへまとめて渡さない。

## 更新・停止・削除・復元の案

APIとSQLiteは[Docker手順](docker.md)で起動・更新する。デプロイはCIで検証したイメージを使う。定期収集はVM/APIの稼働中だけ実行し、停止中の時刻を追い掛けない。

稼働を止める場合はまずアプリを正常停止し、VMを停止する。停止中もディスク・予約IP・バックアップの料金は残る。完全に終了する場合は必要なバックアップを別DBで復元確認し、VM・不要なIP・不要なディスク・保存バケットを個別に確認して削除する。データ削除は稼働停止とは別の判断とする。

バックアップは稼働中SQLiteの正式なbackup APIを使い、成功・整合性確認後に外部へ送る。取得またはアップロード失敗を成功扱いにせずログに残し、古い世代を維持する。復元はまず別DBで記事・気になる・ピン・既読を確認し、本番を停止してから切り替える。ファイルの単純コピーや稼働中DBへの上書きはしない。7日分より古い誤操作や、最後に成功したバックアップ以降の操作は復元できない。
