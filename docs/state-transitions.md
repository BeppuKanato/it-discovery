# 状態遷移図

更新日：2026-10-15

[READMEに戻る](../README.md) · [アプリのルール](rules.md) · [ユースケース](use-cases.md)

記事の状態、一回の仕分けの進行、記事の保持と削除を分けて表す。四角は状態、矢印は状態を変える操作・出来事を表す。`[条件]` はその遷移が可能な条件、`／` の後は遷移時に行う処理を表す。

図はMarkdown内のMermaidコードとして編集でき、GitHub上で表示される。未決事項を新しい仕様として確定させず、末尾にまとめている。

## 1. 記事の状態

閲覧・気になる登録・ピン止めは独立した状態で、同時に成立する。例えば「既読・気になる登録済み・ピン止めあり」の記事も存在する。破線の区切りは、この3つの状態を同時に持つことを表す。

初期状態は新規記事を取り込んだときの状態。既存記事を再取得した場合は、状態を初期化しない。

```mermaid
stateDiagram-v2
    state "記事の状態（3つを同時に持つ）" as Article {
        state "閲覧" as Reading {
            [*] --> Unread
            state "未読" as Unread
            state "既読" as Read
            Unread --> Read: 外部タブ作成と遷移依頼を受け付けた
            Read --> Read: 再び開く／最後に開いた日時を更新
        }
        --
        state "気になる登録" as Interest {
            [*] --> NotInterested
            state "未登録" as NotInterested
            state "登録済み" as Interested
            NotInterested --> Interested: 気になるに登録
            Interested --> NotInterested: 一覧で登録解除
            Interested --> NotInterested: 戻す [同じ仕分け回で行った登録]／登録を取り消す
        }
        --
        state "ピン止め" as Pinning {
            [*] --> Unpinned
            state "なし" as Unpinned
            state "あり" as Pinned
            Unpinned --> Pinned: 一覧でピン止め
            Pinned --> Unpinned: 一覧で解除
        }
    }
```

仕分け開始時の対象は、**未読・気になる未登録・ピン止めなし**の記事。

登録済みから「戻す」で未登録になるのは、その回で右スワイプして選んだ仮の登録を取り消す場合だけ。以前から登録済みの記事を仕分け対象に出して外す意味ではない。

この図の「気になる」は利用者の判断を表す。仕分け中は手元の仮の登録を変更し、DBへの保存は終了時にまとめて行う。途中で閉じた場合は、端末に残った未送信の登録を次の起動時に送る。取り消しでDBの登録解除を毎回行うわけではない。保存先と送信の流れは [シーケンス図](sequences.md) を参照。

見送りは記事の永続的な状態ではなく、その回の一時的な記録である。記事の情報が更新されても、閲覧・登録・ピン止めの状態は維持する。

参照：[記事を開く・表示のルール](rules.md#表示記事を開く)、[登録・ピン止めのルール](rules.md#気になるピン止め一覧)。

## 2. 一回の仕分けの進行

カードを表示していることと、その記事が未読であることは別。元記事を開けたら既読になるが、外部サイトから戻ったときは同じカードを表示する。

```mermaid
stateDiagram-v2
    [*] --> Idle
    state "開始待ち" as Idle
    state "カード表示中" as Card
    state "外部サイト表示中" as External
    state "完了画面・終了未確定" as Complete
    state "最終結果を保存中" as Saving
    state "端末保存失敗・操作停止" as LocalFailure
    state "終了画面・通常操作不可" as Stopped

    Idle --> Card: 開始 [対象が1件以上]／最大10件を選ぶ

    Card --> Card: 登録・見送り [次のカードあり]／判断を記録して次へ
    Card --> Complete: 登録・見送り [最後のカード]／判断を記録
    Card --> Card: 次へ [既読・次のカードあり]／進行履歴を記録
    Card --> Complete: 次へ [既読・最後のカード]／進行履歴を記録

    Card --> Card: 戻す [履歴あり]／直前の判断を取り消して前のカードへ
    Complete --> Card: 戻す [履歴あり]／直前の判断を取り消して前のカードへ

    Card --> External: 元記事を開けた／既読にする
    External --> Card: アプリへ戻る／同じカードを表示

    Card --> Saving: 途中で仕分けを終了する／判断済み結果を確定
    Card --> LocalFailure: 端末保存失敗／手元の最新結果を保って操作停止
    Complete --> LocalFailure: 端末保存失敗／手元の最新結果を保持
    LocalFailure --> Saving: 再保存成功 [終了要求中]／送信へ進む
    LocalFailure --> Card: 再保存成功 [判断中・残りあり]／操作再開
    LocalFailure --> Complete: 再保存成功 [終了要求なし・全件処理済み]
    LocalFailure --> Stopped: 終了／未保存変更の消失を通知
    Saving --> Stopped: 終了／保存済みの未送信結果を残す
    Complete --> Saving: 仕分けを終了する／最終結果を端末に確保し一括送信
    Saving --> LocalFailure: 端末保存失敗／送信せず操作停止
    Saving --> Idle: 保存成功または登録対象なし／削除済みを通知し履歴を破棄
    Saving --> Saving: 保存失敗・応答不明／未送信結果を残す

    note left of Idle
        対象が0件なら開始できない
    end note

    note right of Card
        開けなかった場合は既読にしない
        アプリ終了後はその回を再開しない
        未送信の気になるは端末に残す
        DBに保存した登録・既読・ピンは残す
    end note
```

- 「戻す」は前のカードを表示するだけでなく、そのカードで行った判断も取り消す。
- 戻す操作はその回の履歴がある範囲で繰り返せる。完了画面でも終了確定までは使える。
- 見送りは同じ回での再表示を防ぐ。ただし、取り消しで戻る場合は除く。
- アプリを終了した回の再開はしない。端末に保存済みの未送信登録は次の起動時に送るが、カード位置・見送り・取り消し履歴は復元しない。
- 確定した送信対象だけを消す。削除済みは記事ごとに通知して解消する。一時失敗は待機して再試行し、未送信のまま次の回へは進まない。
- 保存中は判断と戻すを停止する。端末保存失敗から再保存した場合、終了要求中だったならSavingへ戻り、判断中だったならカードまたは完了画面へ戻る。
- 元記事を開く操作は判断の取り消し対象ではない。戻す操作で既読を未読に戻さない。

既読カードは左右の判断を行わず「次へ」で進む。最大10件のうち1件として数える。仕分け中の一覧移動は設けない。開始時のカード情報と順番を固定し、収集の追加・更新を割り込ませない。

参照：[仕分けのルール](rules.md#仕分け)。

## 3. 記事の保持と削除

サーバーのDBで気になる登録・ピン止めのどちらかがあれば自動削除から保護される。両方なくなったときに、通常の削除対象へ戻る。仕分け中の仮の登録は、サーバー保存が完了するまでDBの保護状態を変更しない。送信前に削除されていれば記事を再作成せず、その記事だけ登録できなかったと通知する。

```mermaid
stateDiagram-v2
    [*] --> Absent
    state "DBに未保持" as Absent
    state "保持中・保護なし" as Normal
    state "保持中・保護あり" as Protected

    Absent --> Normal: 定期収集 [新規追加可能]／未読で追加

    Normal --> Protected: 気になる登録またはピン止め
    Protected --> Normal: 解除 [気になるもピン止めもなし]

    Normal --> Absent: 削除条件に該当／記事と既読記録を削除

    Normal --> Normal: 同一記事を再取得／情報を更新
    Protected --> Protected: 同一記事を再取得／情報を更新

    note right of Protected
        期限・件数超過でも削除しない
    end note
```

「DBに未保持」は未取得・削除済みを表す説明上の状態であり、未保持記事のレコードをDBに残す指定ではない。

### 削除条件

| 条件 | 対象・順序 |
|---|---|
| 保持期限を超えた | 保護されていない未読が対象。取得日時からの保持期間で判定する |
| 件数上限を超えた | 保護されていない未読を、取得日時が古い順に削除する |
| 未読を削除しても件数超過 | 保護されていない既読を、最後に開いた日時が古い順に削除する |

既読記事は期限では削除しない。削除後に同じ記事を再取得した場合、未読として追加されることは許容する。

### 新規追加の停止・再開

保護記事だけで上限に達した場合、新規記事の追加を停止する。既存記事の情報更新は続ける。保護記事が減って空きができれば、次の定期収集タイミングで新規追加を再開する。

参照：[保持・削除のルール](rules.md#保持削除取得停止)。

## 起動・同期の遷移

```mermaid
stateDiagram-v2
    [*] --> Sync
    state "未送信同期・通常操作待機" as Sync
    state "日次判定" as Daily
    state "一覧" as List
    state "仕分け" as Sort
    state "終了画面" as Stop
    state "恒久エラーの解消待ち" as Resolve
    Sync --> Sync: 一時失敗／間隔を空けて再試行
    Sync --> Sync: 削除済み／通知して該当項目を解消
    Sync --> Resolve: 不正要求など／自動再試行を停止
    Resolve --> Sync: 修正または明示的な破棄
    Sync --> Daily: 未送信なし・同期完了
    Sync --> Stop: 終了／未送信を残す
    Daily --> Sort: 当日未判定・対象あり／日付を端末保存
    Daily --> List: 判定済みまたは0件／0件も判定済みにする
    Daily --> Daily: 取得失敗／判定済みにせず再試行
    List --> Sort: 手動開始かつ対象あり
```

日次記録そのものの保存失敗時は通知して一覧へ進み、自動再開始を繰り返さず手動開始を残す。日付の境界は日本時間の午前0時。開きっぱなしの画面へ突然仕分けを割り込ませない。

Issue #4の操作仕様は[操作方針](operation-policy.md)に確定した。複数端末の同時操作や仕分け中のピン操作など、残る範囲は[ルールの未決事項](rules.md#未決事項)を参照。
